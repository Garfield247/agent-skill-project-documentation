# 人机三态正交文档体系与 PROJECT_MAP 语义锚点自愈 (Three-Tier & Pointer Map)

## 1. 人机双重视角·三态正交文档治理体系

彻底解耦“AI 规则”、“人类知识库”与“过程性报告”，坚决防止文档混乱与 Git 脏提交：

| 状态类别 | 物理落盘位置 | Git 追踪 | 核心定位与治理原则 |
| :--- | :--- | :---: | :--- |
| **第一态：AI 机器规则态** | `<project>/.agents/rules/` | ✅ 必须追踪 | 专给 AI 注入的约束指令，高熵极简，单文件 ≤ 200 行。使用 `@[...]` 语法引入公共总纲。 |
| **第二态：人类持久知识库** | `<project>/project_wiki/` 或 `docs/` | ✅ 必须追踪 | 团队与 AI 共享的**唯一业务与架构真理库 (SSOT)**，包含 Diátaxis 编号目录、时序图、DDL 字典。 |
| **第三态：瞬态/过程态工件** | `<project>/.scratch/` 或 `.agents/reports/` | ❌ 严禁追踪 | AI 临时诊断、压测对比报告，默认在 `.gitignore` 中排除，阅后即焚，严禁污染业务库。 |

## 2. `<project>/.agents/rules/00_project_map.md` 语义锚点与自愈机制

绝对行号属于“脆弱指针”，他人改动数行即可错位。指针格式**强制同时声明章节标题与预估行号**：

```markdown
<!-- ✅ 生产级自愈写法：章节语义锚点 + 预估行号区间 + 锚点文本 -->
- 订单流转有限状态机:
  👉 [order_state.md#3.2-状态流转矩阵](file://${WORKSPACE_ROOT}/project_wiki/02_架构设计/order_state.md#3.2-状态流转矩阵) (约 L45-L90，锚点: `## 3.2 状态流转矩阵`)
```

### 调阅与 0 误差自愈 SOP
1. **预估区间切片调阅**：Agent 先通过预估行号区间调用 `view_file(StartLine, EndLine)`；
2. **锚点校验断言**：Agent 校验切片首部是否包含目标章节锚点（如 `## 3.2 状态流转矩阵`）；
3. **行号偏移自动修正**：若未命中锚点，Agent **严禁盲目读取错误上下文，必须立即在原文件中检索该锚点并重新精准切片**，实现 100% 自动自愈。
