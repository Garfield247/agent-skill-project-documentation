# Diátaxis 四象限框架与分层治理结构 (Diátaxis & Hierarchy)

## 1. 智能目录探测 (Folder Discovery)

在创建或查阅文档前，必须在当前操作项目根目录下执行探测：
1. 检查是否存在既有技术文档目录：`project_wiki/`、`docs/`、`wiki/`、`documentation/`；
2. 若命中任意既有目录：一律沿用该目录，保持项目历史风格统一；
3. 若均不存在：根据行业通用惯例，初始化创建通用的 `project_wiki/` 或 `docs/` 目录；
4. **绝对红线**：严禁在系统根路径或父级无关目录中新建文档！

## 2. Diátaxis 四象限显式编号分层目录架构

严禁把全工程所有设计说明书、接口文档、部署配置全部平铺混杂：


## 3. 00 号规范目录防膨胀架构：“速查总纲 + 领域分册”治理范式

> 🚨 **核心工程铁律**：**严禁在 `00_标准与规范/` 下编写超千行、数十 KB 的单体“巨无霸规范总纲”（巨无霸文档对 AI 是致命灾难）！必须遵循“高熵速查总纲 + 领域专项分册”的解耦架构。**

### 3.1 巨无霸规范文档对 AI 的三大致命杀伤力
1. **注意力中间塌陷 (Lost in the Middle)**：大模型对 1000+ 行文档中间 20%~80% 区域的关注度急剧衰减，深水区核心红线极易被假装读过而实际漏看；
2. **认知过载与逻辑发散**：编写单一业务 Logic 时，塞入前端分页、Git 格式等无关噪音，破坏 Agent 专注度；
3. **首字延迟暴增与 Token 黑洞**：每次对话重复吞入上万 Token，极大加速上下文被动截断。

### 3.2 标准“速查总纲 + 领域分册”拓扑标杆
```text
project_wiki/00_标准与规范/
├── 00_全局工程红线速查总纲.md           🔥 [核心宪章 ≤100行] (仅保留 10 大不可违背的绝命红线与分册索引，AI 必读)
├── 01_代码分层与命名规范.md             📘 [分册 ~120行] (双轨命名、防上帝文件、严禁跨 Logic 调用)
├── 02_API契约与接口设计规范.md          📘 [分册 ~120行] (路由动词、模块化契约拆分、禁裸 Map、雪花精度)
├── 03_数据库与缓存持久化规范.md         📘 [分册 ~150行] (软删除原子复活、JSON 强类型落库、按月分表)
└── 04_防御性编程与异常处理规范.md       📘 [分册 ~100行] (零吞异常、指针语义防零值、多字节截断、统一响应与错误码)
```

### 3.3 人机双重视角收益
- **AI 视角**：进场秒级吸收 00 号速查总纲（仅 800 Token），开发某一领域（如写 SQL）时按需精准切片对应分册（2000 Token），依从度拉满；
- **人类视角**：彻底终结千行文档滚屏翻找地狱，修改某一领域规范只产生单文件清晰 Git Diff。
